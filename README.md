# GVK-Derelicts
NPC encounter content (MES/RivalAI) for the GV: Deserts of Kharak server.
- Terms used in this repo (Unit, Wreck, Convoy Contract, Territory, ...): `GLOSSARY.md`.
- Work, ideas and upstream MES fixes: GitHub issues in GV-Server-Mods/GVK-Settings ([open `area:npc` issues](https://github.com/GV-Server-Mods/GVK-Settings/issues?q=is%3Aissue+is%3Aopen+label%3Aarea%3Anpc), [open `upstream` issues](https://github.com/GV-Server-Mods/GVK-Settings/issues?q=is%3Aissue+is%3Aopen+label%3Aupstream)). There is no TODO list and no TODO comments in the SBC files.
- Tables between `GENERATED` markers are rebuilt from the SBC files by `tools/Update-DocTables.ps1`; don't edit them by hand.

## Territory size
Each alliance faction's Influence (`KHAANEPH_Influence` / `SOBAN_Influence`) sets its Territory radius through `GVK-Alliance-Events-ZoneSize.sbc` (one MES Event per faction, 12 conditions mapped 1:1 to 12 actions):

| Influence | Zone radius |
| --- | --- |
| `< 200` | 10 km |
| `200 - 399` | 20 km |
| `400 - 599` | 30 km |
| `600 - 799` | 40 km |
| `800 - 999` | 50 km |
| `>= 1000` | 55 km |

Counters are clamped to a floor of 0 and a ceiling of 1200 every evaluation cycle, and every chat message names the direction the territory moved.

Run command `/MES.Debug.ChangeCounter.Value1.Value2` to adjust counters. This is an additive command, so use positive or negative amounts.


https://github.com/MeridiusIX/Modular-Encounters-Systems/wiki/Admin-&-Configuration:-Admin-&-Debug-Options#debug

`/MES.Info.GetGridBehavior` or `/MES.Info.GetGridData` are not currently on the admin debug command wiki

To get large wrecks to spawn: `/MES.Debug.ChangeBool.LargeWrecksEnabled.true`

Coalition convoys (Routes A, B, E) no longer spawn on their own; they spawn only through Convoy Contracts on the `NTS [COAL] Base` contract board.

Other useful commands:
`/MES.Debug.ClearUniqueEncounters`
`/MES.Debug.ClearStaticEncounters`

# Notes
1. Chat SendToAllPlayers will also be received by SEDB when set to send server messages.
2. To avoid this, use `SendToAllOnlinePlayers:false`, `IgnoreAntennaRequirement:true`, and a very large override range.
3. Don't use UseSurfaceHoverThrustMode at the same time as FlyLevelWithGravity.
4. When using UseSurfaceHoverThrustMode, ensure WaypointTolerance is less than HoverPathStepDistance.
5. The UseSurfaceHoverThrustMode works well for wheeled rovers on planets, but use HoverPathStepDistance less than 100 for rougher terrains.
6. Planet rovers with suspension need hidden NPC thrusters and gyros to operate because MES has no suspension controls.
7. Set the planet rover suspension friction very low, like 12% or less, to allow it to turn reasonably.
8. Use Patrol behavior for random encounters and a trigger sequence to switch between aggressive behaviors with secondary autopilots.
9. Use a Manual Trigger where multiple triggers need to operate the same action to prevent repeated trigger actions.
10. KPLs survive restarts and merge correctly as of MES 2.74.04. A KPL with a timer of 0 or less is not created, so permanent KPLs are not possible; use a long timer instead.
11. `UseFailCondition` and `UseElseActions` don't appear to work with Timer Triggers because the timer always succeeds.
12. Particles can be played similarly to sounds, but are undocumented in the wiki.
13. Condition Profiles do not work correctly with some static SpawnGroups; instead, use those tags in the SpawnGroup directly.
14. Do not raze blocks that could be on subgrids; this can lead to a crash.
15. Do not use the GenerateExplosion and raze functions simultaneously near the same block (like RAI Remote); this can lead to a crash.
16. `BountyOnKill=3000000;` can be put directly in the behavior profile when using this mod https://steamcommunity.com/sharedfiles/filedetails/?id=2812148664
17. `ResetThisStaticEncounter:true` and `ForceDespawn:true` can remove and reset static encounters, but are undocumented in the wiki.
18. Strike behavior needs a good amount of distance to line up and attack. Set the min and max offset distances at least 800 m beyond the fixed guns' max target distance, so the run is lined up before the target is in range (Strike Fighter: gatlings reach 1600 m, offsets 2400-2800 m; Chad Shuttle and GR-650: 2000 m, offsets 3000-3400 m). Widen the target profile's `MaxDistance` and `MaxExistingTargetDistance` and the `TargetNear`/`TargetFar` distances to cover offset plus the turn-around (about 1 km), or the target is dropped between passes.
19. StrikeBeginPlanetAttackRunDistance is measured from the min and max offset distance waypoint; keep this low, around 100m.
20. If IdealPlanetAltitude is way higher than MinimumPlanetAltitude, it will climb too sharply and disturb its angle of attack.
21. NPCs are awful at aiming at targets. Use Keen AI blocks instead of RAI autopilot if accuracy is critical.
22. `ProcessAsAdminSpawn:true` is available for Spawner profiles to bypass some restrictions.
23. Use `[IgnoreCleanupRules:true]` on all NPCs with aggressive MES CleanUp settings to help delete debris that doesn't have an active RAI block.
24. Use `[DebugMessage: enter text here]` in action profiles for a quick way to send a message to chat for testing purposes.
25. Do not use RazeBlocks on an RAI remote control block; doing so can cause a crash at UpdateShape() if the block is split from its parent grid.
26. `MaxActions` is one-way. Once `TriggerCount >= MaxActions` the trigger is force-disabled on every evaluation and RivalAI has no tag to reset the count, so `[EnableTriggers:true]` cannot revive it. Any trigger that must fire again (3h cooldowns, repeatable terminals) must use `[MaxActions:-1]` and disable itself from its own action.
27. `[ActionExecution:Condition]` with `[UseAnyPassingCondition:true]` runs only the action whose index matches the last satisfied condition, so `ConditionIds` and `ActionIds` must be index-aligned and equal in length. This is how one event can host a whole tier ladder instead of one event per tier. Order matters: list clamp conditions last so a clamp wins the tie against a simultaneous tier change.
28. State for MES event tier ladders: use a stateless integer marker, not a boolean matrix. Keep one `<FACTION>_Tier` sandbox counter holding the currently-announced radius. Conditions are pure counter tests: points in band AND `Tier != band` AND direction (`Tier < band` = up-entry, `Tier > band` = down-entry), so every transition announces exactly once with a truthful direction and same-tier re-fires are impossible. Clamps never write the tier marker - the transition action owns it (single writer), so a clamp that resets points gets its zone + chat on the next cycle. The top band must be open-ended (`>= 1000`, no upper bound): the ceiling clamp parks points at exactly the max, so a bounded top band leaves that value dead - no band matches, the zone never resizes, and downstream zone-gated triggers silently refuse. A condition referencing a counter that was never written to sandbox storage ALWAYS fails (MES checks the `GetVariable` success flag - the 0 default does not help), so a one-shot `UniqueEvent:true` bootstrap event whose conditions touch only the Points counters must create the Tier markers first; `RunCount` is serialized, so it fires exactly once per world.
29. RivalAI `[SetBooleansTrue/False]` and `[SetCounters]/[IncreaseCounters]` are grid-scoped, not sandbox. Anything that a MES Event, plugin, or HUD must read needs the `[SetSandboxBooleansTrue/False]`, `[IncreaseSandboxCounters]` etc. variants instead.
30. Preset base deployment (`GVK-Alliance-PresetBases-*`) keeps one live base per site purely through the SpawnCondition RC code gate: `[RemoteControlCode:GVK-Alliance-Base]` with `[RemoteControlCodeMinDistance:1100]`. 1100 must stay above `2 x` the spawner `MaxDistance` (500) or a redeploy can land outside the gate; tower sites are 7.9 km apart at minimum, so the gate never leaks across sites. There is no per-site cooldown: the site frees itself when the base grid is destroyed, and pressing the terminal while a base exists is a silent no-op (the base's own "constructed" chat is the success feedback).
31. MES Event chat messages only substitute `{PlayerName}`. `IdsReplacer` tokens (`{Faction}`, `{EncounterDisplayName}`, sandbox counters, zone names) are applied to sandbox variable names/values, zone names, spawn replace keys and `DebugChatMessage`, but not to event chat text.
32. MES zone radius vs Zone 0: the SOBAN zone centre is 37.2 km and KHAANEPH is 47.0 km from Crossroads Tower, so the 40-55 km tiers overlap the starter hub. NPC spawning there is already gated server-side (COALITION only), but hub players will see alliance zone enter/leave announcements.
33. Before MES 2.74.04, `TriggerSystem.ProcessButtonTriggers` let a player-built button panel on another grid fire a grid's ButtonPress triggers (fixed in MES #360).
34. MES/RivalAI sandbox variables are ONE session-global namespace: two events writing the same bare name fight over the same storage. Live incident: the ZoneSize ladder used bare `Tier10..Tier55` booleans in both the KHAANEPH and SOBAN events; each faction's transitions cleared the other's flags and the two events ping-ponged "decreased to 10km" / "increased to 55km" announcements forever (plus a `-10000` debug counter nudge as the trigger). Prefix every variable that anything else touches with its owner (`KHAANEPH_Tier`, not `Tier`), and keep one writer per variable.
35. The zone ladder's Tier marker tracks the last *announced* radius, not the live zone. Manually resetting/deactivating a zone via debug desyncs the two - the ladder will never re-assert (all band conditions require `Tier != band`), so the zone stays shrunk until points cross a boundary. Recovery: drop the marker below the current band (`/MES.Debug.ChangeCounter.SOBAN_Tier.-45`) and the ladder re-Sets the radius within one 5 s cycle.
36. MES substituted `{Faction}` (the NPC's own faction tag) into RivalAI sandbox counters and booleans (`TriggerSystem.SetSandboxCounter`/`SetSandboxBool`), so own-faction counter changes are faction-agnostic: `GVK-Alliance-TriggerTags-Influence.sbc` Despawned/Awarded triggers were consolidated to one pair per encounter type using `[DecreaseSandboxCounters:{Faction}_Influence]` / `[IncreaseSandboxCounters:{Faction}_Influence]`, and their trigger tags dropped the faction suffix (hub now references `...-{EncounterType}` only). `[SetSandboxStrings]` and `[SetCustomStrings]` values run the full IdsReplacer, so `[CustomStrings:DecreaseFactionName,{Faction}]` feeds the shared chat profiles. The Compromised transfer (decrease own + increase rival) still needs one pair per faction: `SetSandboxCounter` only substitutes `{Faction}`, there is no rival/opposing-faction token, and trigger `[Actions:]` references resolve statically at profile load. Revisit if MES adds full IdsReplacer (or `{OpposingFaction}`/CustomStrings support) to `SetSandboxCounter` - `{Faction}`-based lines will need no rework when that lands.
37. NPC chatter lines live in dialogue banks, `Content/Data/DialogueBanks/GVK-<Category>-<FACTION>-<Tier>.xml`, generated by `Docs/dialogue/scripts/build_banks.py` from one draft per voice in `Docs/dialogue/drafts/` (edit the drafts, never the XML). Tier sets chat range from the behavior's Encounter Type: Small 5 km, Medium 15 km, Large server-wide; lines tagged `[S]`, `[M]` or `[L]` in a draft only go to that tier. Categories: `Units`, `Travellers` (Traders, Transports, Freighters), `Structures` (alliance Base, Outpost, Turret) and `Installations` (PlanetaryInstallation grids and the Downed Salvager). Each behavior picks its bank with `[DialogueBanks:]`, and the chatter triggers play a cue with `[PlayDialogueCue:true]` + `[DialogueCueId:]`; the DefeatedAndAttacked group plays `NeutralAttacked`, `EnemyAttacked` and `FriendlyFire` on every grid that has a bank (GAALSIEN and DERELICT banks skip the cues their faction can never hear). Small wrecks have no bank and Small Units have no `Defeated` lines, so only the blue Sensors message marks them. The bank is fixed per behavior, not per `{Faction}`, so a behavior shared by two factions needs a copy per faction, marked `[//CopyOf:<original>]`: the generic Small/Medium/Large installation behaviors are DERELICT and their GAALSIEN spawn groups use `-GAALSIEN` copies, and KHAANEPH Salvagers use `GVK-Unit-Encounter-Behavior-Salvager-KHAANEPH`, a copy of the GAALSIEN one. MES (checked against `13bcb1d`) keeps **one** chat profile instance per bank for every grid that uses it, and `ProcessChat` stores `ChatSentCount` and the `MinTime`/`MaxTime` cooldown on that instance. So limits on a bank's chat profile apply to every NPC using that bank file, server-wide. GVK uses that on purpose: `[MinTime:8]`/`[MaxTime:12]` on the `GVK-Universal-Chat-Voice-*` profiles is the squad throttle, one line per bank every 8-12 s however many Units speak at once (lines blocked by it are dropped, not queued). Keep the window short, since a long one silences a whole voice, and never set `[MaxChats:]`, which would use up the voice until restart. Per-unit pacing stays on trigger cooldowns. The profiles are at `[Chance:100]`; each cue's action rolls its own `[Chance:]` (callouts 50, EnemyAttacked 25, Defeated 50, NoTargets 20, NeutralAttacked and FriendlyFire 100). A failed roll skips the whole action and still uses up the trigger's cooldown, so the Defeated cue has its own action, apart from the defeat logic. Don't set `CustomChatAuthorName` on these Units either: MES writes it into the shared profile's author. `audit_mes_references.ps1` lists every shared `GVK-Universal-Chat-Voice-*` profile as a "Shared Chat Profile" warning (27 today); that is this design, not a defect.
38. MES (checked against `13bcb1d`) loads every base-game `IsPlanetaryEncounter` spawn group (`P1_SupplyPost` to `P30_AbandonedFarmstead`) as a Planetary Installation, even with the world's planetary encounters off, so they mix into the wreck pools. `GVK-Universal-SpawnGroup-VanillaPlanetaryDisabled.sbc` redefines them with `<Enabled>false</Enabled>`, which MES skips. Their prefabs stay loaded and can still be used in GVK spawn groups. When a game update adds new `P*` groups, copy them into that file. The reference audit (se-dev-mes 1.8.1+) knows the base-game prefabs, so it no longer flags them.
39. Wreck prefab checklist (Small `NWS` / Medium `NWM`; checked against MES `13bcb1d`):
    - **Loot:** the main loot profile fills small/large cargo containers (`GVK-Universal-Loot.sbc`): Small wrecks need 4-6, Medium 8-12. Conveyor junctions, straight conveyor tubes and AI combat/mission blocks count, because `GVK-Replacer-ConveyorToCargo` turns them into containers at spawn.
    - **Adding containers:** swap a 1x1x1 block for a small cargo container in place (same size only, never remove blocks). Order: remaining conveyor shapes and AI blocks, then timers, event controllers, turret controllers, gyros (keep 1) and reactors (keep 1), batteries last (keep 2). Never swap `MA_Buster_Conveyor`; it holds turrets.
    - **RivalAI block:** needs a Remote Control, a `LargeBlockCockpitSeat`/`LargeBlockCockpitIndustrial`, or a flight AI block (the last two are swapped in by `GVK-Replacer-LargeCockpitToRivalAI`). Without one the wreck behavior is never applied.
    - **Beacon:** required for a planetary installation; range 5 km Small, 30 km Medium, no HUD text. Antennas off, welders and projectors off, projector blueprints removed.
    - **Placement:** vehicles use the `Wreck` spawn conditions (random rotation), buildings the `Building` ones (none).
    - **Names:** the file name, prefab `Subtype`, main grid `DisplayName` and the spawn group's `<Prefab SubtypeId>` all match.
40. An escort never retreats (checked against the MES fork at `5fd61d1`). MES `Escort.cs` waits `WaypointWaitTimeTrigger` for a valid leader and then switches to Retreat for good; nothing in MES leaves Retreat. So:
    - A leader answers an escort request only when it assigned the slot: the single-slot peer leaders gate on `GVK_Peer_SlotSpent`, and the Elite/Convoy `GVK_EscortAssigned` reply carries `[MatchReceiverEscort:true]`, which delivers it only to a unit that is an active escort of that sender.
    - A unit that gets no slot goes back to Patrol on the 4 s `ReturnToPatrol` timer, before the 5 s or longer wait on its autopilot profile. Every escort-capable Primary profile keeps `WaypointWaitTimeTrigger` at 5 or more; the Scouts that set 0 use the peer system (note 41), which confirms the slot before the unit converts.
    - Native-Escort convoy units (`GVK-Convoy-Escort-Behavior-*`) use `LeaderLost`, `LeaderFound` and a 15 s `NoLeader` timer to switch to Horsefly. A Salvager drops its escort role 60 s before its 1800 s retreat timer.
    - MES frees an escort slot only when the escort grid is gone or no longer AI-ready (`EscortSystem.cs`); an escort that stays alive but returns to Patrol, or whose leader dies, leaves the slot marked used. A peer leader has exactly one slot, so once it has handed that slot out it never offers again (`GVK_Peer_SlotSpent`, kept for the life of the grid). That does not make a pair permanent: a wing that loses its leader goes back to Patrol and pairs with a different free peer, and a leader that lost its wing can still become someone's wing. A cruiser has two slots, so one leaked slot costs it half its capacity, not all of it.
    - Every leader needs `[EscortOffsets:]`: without one it answers every request with "No Available Offsets". Cruisers carrying `GVK-ConvoySystem-Leader-TriggerGroup` (Elite and the defense cruisers: Honorguard, HoverCruiserHorsefly, LargeRoverHorsefly, ProductionCruiser) have two slots at `{X:150 Y:0 Z:0}` and `{X:-150 Y:0 Z:0}`; the Convoy leads have four to six.
41. Peer escort pools: Scouts and Fighters escort each other, never cruisers. `tools/New-PeerEscortPool.ps1 -Pool <Name> -Radius <m>` generates `Unit-All-TriggerGroup-PeerEscort-<Name>.sbc` with its own `GVK_Peer<Name>_*` command codes, so two pools never hear each other. Pools today: **Land** (LAV, Sandskimmer, SmallHoverHorsefly; 1500 m) and **Air** (Strike Fighter, Interceptor; 3000 m). To add a pool, run the script, replace the member behaviors' `GVK-ConvoySystem-Escort-TriggerGroup` with `GVK-Unit-All-TriggerGroup-PeerEscort-<Name>` and add one `[EscortOffsets:{X:.. Y:0 Z:..}]` line (Land `{X:40 Y:0 Z:30}`, Air `{X:150 Y:0 Z:100}`; +X is right and +Z is behind the Remote Control). Flow: a free peer offers on a random 8-20 s timer; another free peer of the same faction asks for the slot while staying in Patrol; the leader assigns the slot (`AssignEscortFromCommand`) and only then replies, and the asker converts to Escort with its leader already set, so `Escort.cs` never sees an empty parent. A Compromised peer sends `LeaderDead` to its wing and `WingLost` to its leader. A wing that loses its leader goes back to Patrol and can pair again; a peer that has led once can only be a wing afterwards. Wings stay out of the Horsefly and Strike switches through the `NotEscortRole` condition. Needs the MES fork (`MatchReceiverEscort`, `MatchReceiverLeader`). Peer wings do not yet share the "defend my leader" commands the cruiser escorts use. Not yet tested in game: the Air pool, since planes need formation flying that `Escort.cs` was not designed for; if it fails, remove the group from the four Air behaviors and keep target sharing (`GVK-Universal-TriggerGroup-ReceiveTargets`).
42. KOTH 5 km zones: the zone whitelist (`GVK-Universal-Zone.sbc`) only checks where the player stands, but MES places a planetary installation or Unit 3-15 km from the player, so a spawn from outside can land inside. `GVK-Universal-TriggerGroup-DespawnInKOTH` despawns anything that lands in a `KOTH Site 0N 5000` zone, like `DespawnInZ0` does for Zone 0. All installation, alliance and COALITION/SOBAN/KHAANEPH Unit behaviors include it. GAALSIEN Units do not: the whitelisted ones are the KOTH garrison. MES spawn conditions can only require a zone, never exclude one, so a trigger is the only way. Such a despawn counts as Lost (chat, points, Defense refund), as in Zone 0.
43. Server build: the escort, leader and Defense refund commands rely on the GV-Server-Mods MES fork (`MatchReceiverParent`, `MatchReceiverEscort`, `MatchReceiverLeader`; MeridiusIX/Modular-Encounters-Systems#384). On released MES the tags are ignored, so a command reaches every same-owner grid in range and `GVK_LeaderDead` would strip unrelated escorts. Check the dedicated server loads the fork before deploying.
44. Admin notes: MES keeps a static encounter by its spawn group name, so renaming a static spawn group (or changing its `RemoteControlCode`) spawns a second copy beside the one already in a saved world; clean the old one up first. Store prefabs in `Content/Data/StorePrefabs/` must never ship a `.sbcB5` older than its `.sbc`: Keen loads the `.sbcB5` instead of the edited XML (`audit_prefabs.ps1` lists them; `-CleanStaleB5` deletes them).
45. Freighter dispatch follows Supply Depot demand. The sandbox counter `<FACTION>_DepotDemand` counts that faction's owned depots whose restock is due: an owned depot adds 1 when it is captured and every 3 hours after its last restock (once; its grid boolean `DemandRaised<FACTION>` stops it counting twice), and takes its 1 back when a Freighter's restock command reaches it, or when it changes hands or leaves every zone (depots are invulnerable and permanent, so there is no destroyed or removed case). The `GVK-Alliance-Event-SpawnFreighter-<FACTION>` event spawns a Freighter every 3 hours only while the counter is at least 1, so a faction with no owned depot, or none due, gets none. One Freighter serves every due depot at once: only depots that are due answer its waypoint requests, up to 4 are queued and visited in the order they answered, and the spawn condition (remote control code ``Freighter_<FACTION>``, minimum distance 999999) keeps a second Freighter from spawning while one is flying. A depot that becomes due after the Freighter has collected its waypoints waits for the next 3-hour spawn. Depot ownership comes from the faction zone that covers it, not from Influence directly. MES offers no inventory check, so "needs restocking" is the timer, not the cargo contents. The counter is created by the first depot request; a missing counter never passes the event condition.
