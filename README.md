# GVK-Derelicts
NPC encounter content (MES/RivalAI) for the GV: Deserts of Kharak server.
- **Load the two skills first, every time.**
  - `se-dev-mes`: MES and RivalAI tags, engine traps, autopilot tuning and debug commands.
  - `se-dev-kharak`: factions, zones, alliances and territory, and season operations.

  This README only covers how GVK-Derelicts itself is built. Anything general lives in those skills and isn't repeated here.
- **Debug visually before logging.** MES logs are slow to work through, so look first:
  - `/MES.Debug.DrawPaths` shows every NPC's waypoint lines, which is how to check autopilot behavior.
  - `/MES.Debug.ShowAllZones` draws zones and KPLs.
  - `/MES.IGGB` on a grid shows its mode, subclass and autopilot state.

  Turn on logging only when these don't explain it. Details: se-dev-mes `diagnostics_and_troubleshooting.md` §2.D and §3.
- Terms used in this repo (Unit, Wreck, Convoy Contract, Territory, ...): `GLOSSARY.md`.
- Work, ideas and upstream MES fixes: GitHub issues in GV-Server-Mods/GVK-Settings ([open `area:npc` issues](https://github.com/GV-Server-Mods/GVK-Settings/issues?q=is%3Aissue+is%3Aopen+label%3Aarea%3Anpc), [open `upstream` issues](https://github.com/GV-Server-Mods/GVK-Settings/issues?q=is%3Aissue+is%3Aopen+label%3Aupstream)). There is no TODO list and no TODO comments in the SBC files.
- Tables between `GENERATED` markers are rebuilt from the SBC files by `tools/Update-DocTables.ps1`; don't edit them by hand.
- Notes keep their numbers because issues cite them; removed numbers are not reused.

# Notes
**28.** Territory tier ladder (`GVK-Alliance-Events-ZoneSize.sbc`): one event per faction runs the whole ladder with `[ActionExecution:Condition]` (se-dev-mes `profiles_and_tags.md` §2.G).
- **State:** one `<FACTION>_Tier` sandbox counter holding the currently announced radius, not a boolean matrix. Bare shared names (`Tier10..Tier55`) once made the SOBAN and KHAANEPH ladders overwrite each other.
- **Conditions:** points in band AND `Tier != band` AND direction (`Tier < band` going up, `Tier > band` going down). So every transition announces exactly once, in the right direction, and the same tier never re-fires.
- **Clamps:** they never write the Tier marker; the transition action is its only writer. A clamp that resets points gets its zone and chat on the next cycle. Clamp conditions are listed last, so a clamp wins a tie against a tier change.
- **Top band:** open-ended (`>= 1000`). The ceiling clamp parks points at exactly the max, so a bounded top band would leave that value matching no band.
- **Bootstrap:** a one-shot `UniqueEvent:true` event creates the Tier counters first, because a counter that was never written fails every condition.

**30.** Preset base deployment (`GVK-Alliance-PresetBases-*`) keeps one live base per site purely through the SpawnCondition RC code gate: `[RemoteControlCode:GVK-Alliance-Base]` with `[RemoteControlCodeMinDistance:1100]`.
- **The 1100 m gate** must stay above `2 x` the spawner `MaxDistance` (500), or a redeploy can land outside it. Tower sites are 7.9 km apart at minimum, so the gate never leaks across sites.
- **No per-site cooldown:** the site frees itself when the base grid is destroyed. Pressing the terminal while a base exists does nothing; the base's own "constructed" chat is the success feedback.

**35.** The zone ladder's Tier marker tracks the last *announced* radius, not the live zone. Resetting or deactivating a zone by hand desyncs the two. The ladder then never re-asserts (every band condition requires `Tier != band`), so the zone stays shrunk until points cross a boundary.
- **Recovery:** drop the marker below the current band (`/MES.Debug.ChangeCounter.SOBAN_Tier.-45`), and the ladder sets the radius again within one 5 s cycle.

**36.** Influence changes use `{Faction}`. `GVK-Alliance-TriggerTags-Influence.sbc` has one Despawned/Awarded trigger pair per Encounter Type, using `[DecreaseSandboxCounters:{Faction}_Influence]` / `[IncreaseSandboxCounters:{Faction}_Influence]`; their trigger tags reference `...-{EncounterType}` only. `[CustomStrings:DecreaseFactionName,{Faction}]` feeds the shared chat profiles. The Compromised transfer (own faction down, rival up) still needs one pair per faction, because MES has no rival-faction token.

**37.** NPC chatter lines live in dialogue banks, `Content/Data/DialogueBanks/GVK-<Category>-<FACTION>-<Tier>.xml`, generated by `Docs/dialogue/scripts/build_banks.py` from one draft per voice in `Docs/dialogue/drafts/`. Edit the drafts, never the XML.
- **Tier** sets chat range from the behavior's Encounter Type: Small 5 km, Medium 15 km, Large server-wide. Lines tagged `[S]`, `[M]` or `[L]` in a draft only go to that tier.
- **Categories:** `Units`, `Travellers` (Traders, Transports, Freighters), `Structures` (alliance Base, Outpost, Turret) and `Installations` (PlanetaryInstallation grids and the Downed Salvager).
- **Wiring:** each behavior picks its bank with `[DialogueBanks:]`, and the chatter triggers play a cue with `[PlayDialogueCue:true]` + `[DialogueCueId:]`. The DefeatedAndAttacked group plays `NeutralAttacked`, `EnemyAttacked` and `FriendlyFire` on every grid that has a bank. GAALSIEN and DERELICT banks skip the cues their faction can never hear.
- **Last words or Sensors:** a defeated grid plays its bank's `Defeated` line every time instead of the blue Sensors "destroyed" message, so a kill gets one message, never both. Only Small Units (no `Defeated` lines) and behaviors with no bank (small wrecks, the Research Lab) get the Sensors message: the DefeatedChat triggers need `GVK_NoLastWords` for every other Encounter Type, and a no-bank behavior must set it at init (Test-Docs checks). The squad throttle can drop a last-words line, so a kill in a busy fight may go unannounced.
- **One bank per behavior:** a behavior shared by two factions needs a copy per faction, marked `[//CopyOf:<original>]`. The generic Small/Medium/Large installation behaviors are DERELICT, and their GAALSIEN spawn groups use `-GAALSIEN` copies. KHAANEPH Salvagers use `GVK-Unit-Encounter-Behavior-Salvager-KHAANEPH`, a copy of the GAALSIEN one.
- **Squad throttle:** `[MinTime:8]`/`[MaxTime:12]` on the `GVK-Universal-Chat-Voice-*` profiles allows one line per bank every 8-12 s however many Units speak; lines blocked by it are dropped, not queued. Keep that window short, since a long one silences a whole voice. Never set `[MaxChats:]`, which would use up the voice until restart. Per-unit pacing stays on trigger cooldowns.
- **Chance:** the profiles are at `[Chance:100]`, and each cue's action rolls its own `[Chance:]`. A failed roll skips the whole action and still uses up the trigger's cooldown, so a rolled cue needs its own action, apart from any logic that must always run. The Defeated cue has no roll.
- **Author name:** don't set `CustomChatAuthorName` on these Units; it would overwrite the shared profile's author.
- **Audit warnings:** `audit_mes_references.ps1` lists every `GVK-Universal-Chat-Voice-*` profile as a "Shared Chat Profile" warning. That's this design, not a defect.

**38.** Base-game `P*` planetary encounters (`P1_SupplyPost` to `P30_AbandonedFarmstead`) are disabled in `GVK-Universal-SpawnGroup-VanillaPlanetaryDisabled.sbc`, so they stay out of the wreck pools (se-dev-mes `spawning_and_conditions.md` explains why MES loads them). Their prefabs stay loaded and can still be used in GVK spawn groups. When a game update adds new `P*` groups, copy them into that file.

**39.** Wreck prefab checklist (Small `NWS` / Medium `NWM`; checked against MES `13bcb1d`):
- **Loot:** the main loot profile fills small/large cargo containers (`GVK-Universal-Loot.sbc`): Small wrecks need 4-6, Medium 8-12. Conveyor junctions, straight conveyor tubes and AI combat/mission blocks count, because `GVK-Replacer-ConveyorToCargo` turns them into containers at spawn.
- **Adding containers:** swap a 1x1x1 block for a small cargo container in place (same size only, never remove blocks). Order: remaining conveyor shapes and AI blocks, then timers, event controllers, turret controllers, gyros (keep 1) and reactors (keep 1), batteries last (keep 2). Never swap `MA_Buster_Conveyor`; it holds turrets.
- **RivalAI block:** needs a Remote Control, a `LargeBlockCockpitSeat`/`LargeBlockCockpitIndustrial`, or a flight AI block (the last two are swapped in by `GVK-Replacer-LargeCockpitToRivalAI`). Without one the wreck behavior is never applied.
- **Beacon:** required for a planetary installation; range 5 km Small, 30 km Medium, no HUD text. Antennas off, welders and projectors off, projector blueprints removed.
- **Placement:** vehicles use the `Wreck` spawn conditions (random rotation), buildings the `Building` ones (none).
- **Names:** the file name, prefab `Subtype`, main grid `DisplayName` and the spawn group's `<Prefab SubtypeId>` all match.

**40.** An escort must never fall into MES's one-way Escort Retreat (se-dev-mes `behaviors_and_autopilot.md` §3D). GVK keeps it out like this:
- **Reply only with a slot:** a leader answers an escort request only when it assigned the slot. The peer leaders gate on their `GVK_Peer_SlotsUsed` counter. The Elite/Convoy `GVK_EscortAssigned` reply carries `[MatchReceiverEscort:true]`, so it only reaches a unit that is an active escort of that sender.
- **No slot, back to Patrol:** a unit that gets no slot goes back to Patrol on the `ReturnToPatrol` timer, before the wait on its autopilot profile runs out. Escort-capable Primary profiles keep a non-zero `WaypointWaitTimeTrigger`. Scouts that set 0 use the peer system (note 41), which confirms the slot before the unit converts.
- **Convoy escorts:** native-Escort convoy units (`GVK-Convoy-Escort-Behavior-*`) use `LeaderLost`, `LeaderFound` and a `NoLeader` timer to switch to Horsefly. A Salvager drops its escort role before its retreat timer runs out.
- **Freeing slots:** MES frees the slot of an escort that died or stopped working the next time the leader gets a request. An escort that leaves while still working frees its slot itself with `[LeaveEscortSlot:true]` (MeridiusIX/Modular-Encounters-Systems#408): peer wings when Compromised or when their leader is lost, convoy-system escorts on `LeaderDead` and `ReturnToPatrol`, and Salvagers when their lifetime runs out. A peer leader's `WingLost` lowers `GVK_Peer_SlotsUsed`, so it can lead again.
- **Offsets:** every leader needs `[EscortOffsets:]`. Without one it answers every request with "No Available Offsets". The cruisers carrying `GVK-ConvoySystem-Leader-TriggerGroup` have two slots, 150 m to each side and 100 m back; the Convoy leads have four to six.

**41.** Peer escort pools: Scouts and Fighters escort each other, never cruisers.
- **Generating a pool:** `tools/New-PeerEscortPool.ps1 -Pool <Name> -Radius <m>` generates `Unit-All-TriggerGroup-PeerEscort-<Name>.sbc` with its own `GVK_Peer<Name>_*` command codes, so two pools never hear each other. Pools today: **Land** (LAV, Sandskimmer, SmallHoverHorsefly) and **Air** (Strike Fighter, Interceptor).
- **Adding a pool:** run the script, then replace the member behaviors' `GVK-ConvoySystem-Escort-TriggerGroup` with `GVK-Unit-All-TriggerGroup-PeerEscort-<Name>`. Add one `[EscortOffsets:]` line (+X is right and +Z is behind the Remote Control).
- **Pairing:**
  - A free peer offers on a random timer, and another free peer of the same faction asks for the slot while staying in Patrol.
  - Each due offer goes out only half the time (`-OfferChance 50`). Peers spawned together otherwise offer at the same moment forever and never pair: both ask, neither answers. MES gives every trigger its own clock-seeded `new Random()`, so their timers repeat in step. The script comment has the code lines.
  - The leader assigns the slot (`AssignEscortFromCommand`) and only then replies. The asker converts to Escort with its leader already set, so `Escort.cs` never sees an empty parent.
  - On Confirm the wing switches to its Tertiary autopilot, a dedicated wing profile: `GVK-Unit-All-Autopilot-AirWing`, `-LAVWing` or `-HoverWing`.
- **Losing a partner:**
  - A Compromised peer sends `LeaderDead` to its wing and `WingLost` to its leader.
  - A wing that loses its leader leaves its slot, goes back to Patrol and can pair again. A leader that loses its wing gets the slot back and can offer again.
  - Wings never take the combat switch of their `Patrol<Name>` group (generated by `tools/New-PatrolSwitchGroup.ps1`), which checks `GVK_Role_Escort`.
- **MES build:** uses `MatchReceiverEscort` and `MatchReceiverLeader`; see note 43.
- **Not yet:** peer wings don't share the "defend my leader" commands the cruiser escorts use.

**42.** KOTH 5 km zones: MES can't keep spawns out of a zone, only require one (se-dev-mes `events_and_zones.md` §4 rule 8), so a spawn requested from outside can land inside a KOTH Site.
- **The fix:** `GVK-Universal-TriggerGroup-DespawnInKOTH` despawns anything that lands in a `KOTH Site 0N 5000` zone, as `DespawnInZ0` does for Zone 0.
- **Who carries it:** all installation, alliance and COALITION/SOBAN/KHAANEPH Unit behaviors. GAALSIEN Units don't, because the whitelisted ones are the KOTH garrison.
- **Effect:** such a despawn isn't a loss. It sets `GVK_DespawnedByRule`, so there is no "lost" chat and no alliance points change; the Defense refund still runs. Zone 0 and the 30-minute outside-faction-zone despawn work the same way, and the latter posts "A {Faction} {EncounterDisplayName} was abandoned." instead.

**43.** Server build: GVK needs an MES release made after master `a1895d9` (2026-10-24). Workshop 2.75.01 is not enough. Older builds ignore the tags or read them differently:
- **`MatchReceiverParent`/`Escort`/`Leader`** (MeridiusIX/Modular-Encounters-Systems#386, 2.75.00): escort, leader and Defense refund commands. Without them a command reaches every same-owner grid in range, and `GVK_LeaderDead` would strip unrelated escorts.
- **`MaxVelocityAngleForSpeedControl:180`** (#402, 2.75.00): before it, a grid drifting away from its waypoint "braked" itself further away.
- **`UseAircraftFlightModel`** (#390, 2.75.00): the Unit aircraft autopilots.
- **`AllowTargetFarWithoutTarget`** (#410, after 2.75.01): the `Patrol<Name>` groups return a Unit to Patrol through it. Without it, a Unit whose target is gone stays in combat.
- **`LeaveEscortSlot`** (#408, after 2.75.01): escorts free their leader's slot (note 40). Without it, a peer leader that lost its wing offers a slot MES still counts as taken.
- **`UseCommandWaypointAsPatrolReference`** (#441, after 2.75.01): leashed Units patrol around their moving parent (note 46). Without it, they patrol around their spawn point.

**45.** Freighter dispatch follows Supply Depot demand.
- **Demand counter:** the sandbox counter `<FACTION>_DepotDemand` counts that faction's owned depots whose restock is due.
  - **Up 1:** when an owned depot is captured, and again every 3 hours after its last restock. That happens once; the grid boolean `DemandRaised<FACTION>` stops it counting twice.
  - **Down 1:** when a Freighter's restock command reaches the depot, or when the depot changes hands or leaves every zone. Depots are invulnerable and permanent, so there is no destroyed or removed case.
- **Spawning:** the `GVK-Alliance-Event-SpawnFreighter-<FACTION>` event checks every minute and spawns a Freighter while the counter is at least 1. A faction with no owned depot, or none due, gets none.
- **One Freighter at a time:** it serves every due depot at once. Only due depots answer its waypoint requests, and up to 4 are queued and visited in the order they answered. The spawn condition (remote control code `Freighter_<FACTION>`, minimum distance 999999) keeps a second Freighter from spawning while one is flying.
- **Late depots:** a depot that becomes due after the Freighter has collected its waypoints waits for the next Freighter, which spawns once the current one is gone.
- **Testing:** `/MES.Debug.ChangeCounter.<FACTION>_DepotDemand.1` raises the demand by hand (undo with `.-1`).
- **Ownership:** comes from the faction zone that covers the depot, not from Influence directly.
- **Restock timing:** MES offers no inventory check, so "needs restocking" is the timer, not the cargo contents.
- **Missing counter:** the counter is created by the first depot request; a missing counter never passes the event condition.

**46.** Parent leash: Units stay near the grid that spawned them, and those Units never create KPLs (GVK-Settings#709; checked against MES `d85b7b3`). Generated by `tools/New-LeashGroup.ps1`.
- **Parent side:** `GVK-Universal-TriggerGroup-LeashBeacon` on every behavior that spawns Units (Defense waves, air support, Elite escorts, Convoy leads, Freighters). Every 5 s it sends `GVK_LeashGround` (3 km) and `GVK_LeashAir` (5 km) with `[MatchReceiverChild:true]`, so only the sender's own children hear it. Each signal carries the parent's position (`GVK-Universal-LeashBeacon-Waypoint-Self`).
- **No owner check:** `[MatchSenderReceiverOwners:false]`, because the owner check is on by default and a parent's children are not always its own faction (a DERELICT wreck spawns GAALSIEN Defense Units, a GAALSIEN wreck GAALSIEN ones, a Freighter its own Defenses and enemy attackers). The child filter alone works for every pairing.
- **Unit side:** every Unit carries `GVK-Unit-All-TriggerGroup-LeashGround` or `-LeashAir`. Hearing the signal sets `GVK_HasParent`, which blocks `CreateKPL`, and moves the Unit's patrol centre to the parent (`[UseCommandWaypointAsPatrolReference:true]`). After 15 s without it, `GVK_AwayFromHome` blocks `GVK-Unit-All-Condition-CanStartCombat` and the GVK-TriggerTags-SwitchToPatrol tag sends the Unit back to Patrol, around where it last heard its parent. The next signal clears it.
- **Letting go:** a Compromised parent sends `GVK_LeashRelease`. A Unit that stays away for 3 more minutes lets go by itself, which covers a parent that despawned or drove out of range. A released Unit patrols around its spawn point again (`[ClearCustomPatrolReference:true]`), fights anywhere and still creates no KPL.
- **Moving parents:** children of a Freighter, cruiser or Convoy lead follow it while they can hear it. Patrol picks up a new centre at the start of its next leg, so they trail a few seconds to a minute behind (GVK-Settings#723). A parent that outruns the 3 km/5 km signal leaves them at the last place they heard it.
- **Static parents:** a wreck or installation sends its own position too, so its Defense Units patrol around it rather than around where they spawned.
- **Children of the other side:** attackers spawned by a Freighter or a GAALSIEN cruiser are its children too, so they hear its leash and stay with it instead of being left behind.
- **Spawn points:** manual Defense waves are placed around the target (`GVK-Universal-Waypoint-DefensesManualSpawn`), not the wreck, so a Unit can start near or outside its 3 km radius. One that never hears the signal acts as a wanderer (KPLs, no leash).

**47.** NPC relations come from two places (checked against MES `103f8d0` and the game build of 2026-10-23). The world-build commands are in the se-dev-kharak skill.
- **MES:** an NPC rates another NPC's grid from the target owner's own reputation with its faction, not from the faction-to-faction relation. With no stored value that is the faction's `StartingReputation`, or -1000 (Enemy) if it has none, and vanilla damage reputation lowers it for every attacker of a non-static faction. COALITION's `StartingReputation` is 500, and MES only counts above 500 as Friends, so every other NPC is Neutral to COALITION. GAALSIEN, DERELICT, SOBAN and KHAANEPH rate every other NPC Enemy, and their target profiles skip the factions they leave alone by tag.
- **Turrets:** vanilla and WeaponCore use the faction-to-faction relation between two NPC factions, and a pair with none set counts as Enemies. Against a player they use the player's own relation with the NPC faction.
- **Targeting:** COALITION Units pick GAALSIEN by faction name (`GVK-Universal-Target-EnemyGAALSIENBeacon`, `-StrikeFighterBeacon`). Forced targets (the attacker, a turret's target, a squadmate's target) go through the override profile instead. COALITION behaviors that fight GAALSIEN set `[OverrideTargetData:GVK-Universal-Target-Override-COALITION]`, which also accepts GAALSIEN by name; every other behavior that can force a target sets `GVK-Universal-Target-Override`, which skips KOTH.
- **KOTH:** Neutral to every NPC faction and to players (static, `StartingReputation` 0), so its weapons with WeaponCore's Neutrals setting on fire on any grid that breaks the KOTH rules, NPC or player. In return no NPC fires on KOTH: MES target profiles skip it by tag, the override profiles above keep a grid it shot from firing back, and every non-KOTH prefab has Neutrals off.
- **Neutrals setting:** only matters for Neutral pairs (KOTH, and DERELICT with COALITION/SOBAN/KHAANEPH). It's off in every prefab except the `NKO [KOTH]` ones, so NPCs ignore Neutrals. Turning it on in an NPC prefab would make that grid fire on KOTH structures.

**48.** Planetary installations never spawn on Rock (GVK-Settings#726; checked against MES `103f8d0`). Every `[PlanetaryInstallation:true]` conditions profile, Units included, has `[InstallationTerrainValidation:true]` and `[DisallowedTerrainTypes:Rock]`.
- **What it checks:** MES reads the terrain type at each candidate spawn spot and skips spots that match. On GVK_Pertam_Planet, Rock is DesertRocks, Stone and Stone_03_Roads, so this keeps installations off roads, cliffs and rocky ground.
- **Limits:** only the centre point is checked, so a large prefab can still overhang a road edge. Rocky regions may get fewer installations, since MES keeps searching further out.
- **Don't add `[UseTerrainTypeValidation:true]`:** it uses the same Allowed/Disallowed lists but checks the most common terrain around the player, so a player standing on rock would block the spawn.
